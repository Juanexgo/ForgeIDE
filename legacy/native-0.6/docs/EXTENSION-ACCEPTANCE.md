# Aceptación del gestor de extensiones 0.4.0

- [x] Gestor accesible sin abrir proyecto.
- [x] Catálogo Open VSX con búsqueda paginada e instalación por ID y versión.
- [x] Inspección antes de instalar, avisos de funciones no compatibles y rechazo de paquetes exclusivamente ejecutables.
- [x] Importación de VSIX de temas y snippets y de paquetes nativos portables.
- [x] Activación global y exclusión por carpeta.
- [x] Actualizaciones manuales individuales/en cola, comprobación opcional al arrancar y versiones fijadas.
- [x] Copia anterior, restauración y recuperación tras desinstalar.
- [x] Exportación/importación revisada de perfiles, sin rutas de proyectos.
- [x] Dependencias nativas con detección de ciclos y bloqueo de contribuciones no disponibles.
- [x] Comandos nativos en la paleta y revisión de sus cambios.
- [x] Inspector y empaquetador de línea de comandos, ejemplo compilado y documentación de la ABI.
- [x] Descargas HTTPS acotadas y comprobación de SHA-256 del registro cuando existe.
- [x] Rechazo de rutas inseguras, enlaces, expansiones excesivas y WASM con importaciones.
- [ ] Host JavaScript compatible con vscode.
- [ ] Marketplace Microsoft y servicio de publicación nativo.
- [ ] APIs generales de vistas, proveedores, keybindings y activación por eventos.
- [x] Arranque en macOS y flujo interactivo de catálogo, ID/versión, revisión e instalación de Gruvbox.
- [ ] Revisión interactiva de todo el ciclo, Windows/Linux, accesibilidad y jornadas largas.

La instalación de un pack muestra sus miembros para inspección individual. Un paquete mixto importa solo las contribuciones admitidas. Los apartados pendientes impiden declarar paridad completa con el ecosistema de VS Code.
